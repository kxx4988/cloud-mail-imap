# 后续计划（网关侧）

本文件记录网关侧后续事项的做法与状态，避免每次重新讨论。已发布的行为看 `CHANGELOG.md`。

当前发布版本：v0.2.33

---

## 1. 网关状态心跳上报（配合主程序显示「在线」）

**为什么必须由网关上报**：主程序跑在 Cloudflare Workers，无法探测网关的 993 / 2465 端口——Workers 没有原始 TCP，`fetch` 也只允许 80 / 443 / 8080 / 8443 等少数端口。所以站点永远不可能「主动看一眼」网关，只能等网关说话。

**约定（待主程序侧同步实现）**

- 网关每小时（间隔可配）向 `${WORKER_BASE}/api/imap/heartbeat` 发一次 POST
- Body 示例：

```json
{
  "key": "<站点签发的一次性/长期 token>",
  "domain": "imap.example.com",
  "version": "0.2.33",
  "certDays": 62,
  "uptime": 86400,
  "ts": 1763600000
}
```

- 站点侧保存 `last_seen` / `version` / `cert_days`，前端显示「在线 · 3 分钟前」，超过阈值（如 2 个上报周期）显示「离线」
- 附带收益：有了 `certDays` 上报，**证书到期告警可以由站点做**（汇总所有部署，不需要每台机器各自配 TG）

**状态**：✅ **已实现（v0.2.33）**。`src/heartbeat.js` 启动即上报 + 每 60 分钟一次，
带 `key / domain / version / certDays / uptime / ts`；`certDays` 用 Node `X509Certificate` 算；
按 body 的 `code` 判结果（站点业务 401 的 HTTP 状态仍是 200）；失败只打 warn，不影响邮件服务。
`install.sh --hb-url / --hb-key` 写进 `.env`，compose 透传。主程序侧 S55 已上线接收端。

## 2. install.sh 结尾提示「回站点保存网关域名」

**背景**：站点无法自动获知网关用了哪个域名（同上，装的时候没告诉站点），只能靠管理员在「系统设置 → 网关部署」里手动保存一次。不保存的话，普通用户看到的是按邮箱域名推断的值。

**做法**：在最终报告的强提醒区块里增加一条（与既有的「安全组放行」「生成应用密码」并列）：

```
回 ${WORKER} → 系统设置 → 网关部署 → 齿轮 → 网关域名填 ${DOMAIN} → 保存
```

**状态**：✅ **已实现（v0.2.33）**。结尾「人工要做」区块增加第 3 条（建议），
提示回站点系统设置 → 网关部署 → 齿轮 → 填 `$DOMAIN` → 保存。

## 3. 证书异常告警

现状：acme.sh 每天 cron 续签，失败只写本地日志；Let's Encrypt 已停发到期提醒邮件，`--email` 现在只是账户联系人，**不会真的发信**。

计划：

- 新增 `--tg-token` / `--tg-chat` 参数，安装时配置 acme.sh notify 钩子（`--set-notify --notify-hook telegram`），配置完**当场发一条测试消息**，发不出去就停下报错
- 每日自检：读证书算剩余天数 + 看 acme.sh 退出码，失败或剩余 < 14 天强制告警
- 每周日发一条心跳（带剩余天数），用来区分「一切正常」和「通知通道本身死了」

**替代方案**：如果先做了第 1 项心跳上报，告警可以直接放在主程序侧做，网关就不需要单独的 TG 配置了。

**状态**：✅ **采用替代方案，网关侧不再实现**。v0.2.33 心跳已上报 `certDays`，
证书到期预警由主程序侧在「网关状态」里展示；网关不再引入 `--tg-token` / `--tg-chat` 与 acme notify 钩子，
避免每台机器各自配一套通知通道。
